# Kristen's Excellent OS v0.1 Data Roadmap

## Current v0.1

The app is live with browser-local persistence for the first capture and review flow.

- Captures are saved in `localStorage` under `kristens-excellent-os-v0.1`.
- Each capture creates suggested review items through the mock AI classifier.
- Review item statuses persist on the same browser/device.
- This is useful for trying the habit and flow immediately, but it is not yet cross-device, authenticated, backed up, or private at the account level.

## Next Required Infrastructure

Supabase should become the system of record before Google integrations and real OpenAI processing are added.

Recommended Supabase tables:

- `users`
- `captures`
- `extracted_items`
- `ideas`
- `writing_fragments`
- `media_items`
- `daily_logs`
- `devotional_entries`
- `lsat_sessions`
- `workout_logs`
- `contacts`
- `calendar_events`
- `integrations`
- `ai_insights`
- `themes`
- `connections`

The central table should be `captures`. Everything starts as a capture, then AI creates one or more extracted items for approval.

## Google Docs End State

Google Docs should be a first-class source and destination.

Planned behavior:

- Import selected Google Docs into captures or writing memory.
- Save writing fragments and essay drafts back to Google Docs.
- Link captures, writing fragments, and drafts to source document IDs.
- Search across manually captured thoughts and selected Google Docs.
- Let AI suggest when a capture belongs in an existing document, outline, or draft.

Likely data fields:

- `google_doc_id`
- `google_doc_url`
- `google_doc_title`
- `sync_status`
- `last_synced_at`
- `source_excerpt`

## Google Calendar End State

Google Calendar should become the execution layer after review approval.

Planned behavior:

- AI suggests calendar blocks from captures.
- User approves before any event is created.
- Approved LSAT, writing, workout, follow-up, and review blocks can become Google Calendar events.
- Calendar events remain connected to the originating capture or extracted item.

Likely data fields:

- `google_calendar_event_id`
- `start_at`
- `end_at`
- `calendar_id`
- `sync_status`
- `origin_capture_id`

## OpenAI End State

The mock classifier should be replaced with an OpenAI extraction function.

Expected output for every capture:

- possible tasks
- reminders
- writing fragments
- ideas
- projects
- people/follow-ups
- devotional entries
- LSAT logs
- workout logs
- media items
- calendar events
- connections and recurring themes

The system rule stays the same: AI suggests, Kristen approves.
